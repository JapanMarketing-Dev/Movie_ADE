# 03. 収録と同期

最終更新: 2026-10-11

## 収録の構成

非表示の収録ウィンドウ（Chromium）で、入力ごとに別々の MediaRecorder を動かす。1つの動画に合成せず、**トラックごとに別ファイル**で保存する。

| トラック | 取得方法 | 保存形式 |
|---|---|---|
| 画面 | `getDisplayMedia`（Electron の `setDisplayMediaRequestHandler` で、選んだディスプレイ／ウィンドウを渡す） | MP4（H.264）、断片化MP4。MP4 を録れない環境では WebM（VP9）に切り替える |
| カメラ（複数可） | `getUserMedia({ video: { deviceId, width, height, frameRate } })` | 同上 |
| マイク（複数可） | `getUserMedia({ audio: { deviceId, echoCancellation: false, noiseSuppression: false, autoGainControl: false } })` | AudioWorklet で 48kHz の PCM を受け取り、WAV に直接書き込む（圧縮しない） |
| PCの音声 | macOS: ScreenCaptureKit のループバック／Windows: WASAPI のループバック（Electron の `audio: 'loopback'`）／Linux: PipeWire / PulseAudio のモニター | WAV |

- マイクの自動補正（エコー除去、ノイズ抑制、自動ゲイン）は**切って**録る。補正は編集時にやり直せる形でかける。
- 画面の映像は既定 30fps。画面の動きが多いものはテンプレートで 60fps にする。
- 収録中は1〜2秒ごとにデータをファイルへ追記する。アプリが落ちても、断片化MP4 / WAV はそこまで再生できる。
- 録画中の目印ホットキー（既定: `⌘/Ctrl+Shift+N` = NG、`⌘/Ctrl+Shift+M` = 重要）。押した時刻を `take.json` に記録する。

### 時刻の記録（アプリ内の同期）

全トラックで同じ単調時計（`performance.now()` と、その時点の `performance.timeOrigin`）を使う。

- 映像: `MediaStreamTrackProcessor` で最初のフレームの `timestamp` を取り、トラックの開始時刻とする
- 音声: AudioWorklet の `currentTime` と、`AudioContext.getOutputTimestamp()` で単調時計に換算する
- `take.json` には各トラックの開始時刻（μs）を記録する。編集時のオフセットはこの差から求める

アプリ内で同時に録ったトラックは、これでフレーム単位に揃う。念のため、カメラの音声（内蔵マイク）とマイクのトラックで相互相関をとって検算し、2フレーム以上ずれていたら警告する。

### 収録後の正規化

MediaRecorder の映像は可変フレームレート（VFR）になる。編集とフレーム単位のチェックで扱えるように、取り込み時に次を行う。

1. ffprobe でフレームの時刻を調べる
2. 固定フレームレート（CFR）の編集用素材を `derived/proxies/` に作る（元のファイルは残す）。GOP は短め（1秒）にしてシークを速くする
3. 低解像度のプロキシ（540p）も作り、プレビューで使う

## 別撮り素材の取り込みと自動同期

### 流れ

```
solocut import C0012.MP4 --take t1
  → ffprobe（fps、VFR か、タイムコード、音声トラック）
  → 編集用素材を作る（必要なら CFR に変換）
  → 音声の相互相関で、アプリ内のマイクのトラックとのオフセットを求める
  → 長尺ならドリフトを推定する
  → sync.json に、オフセット、ドリフト、信頼度を書く
  → 信頼度が低ければ判定モデルへ、それでも低ければ人の確認待ちへ
```

### 同期のアルゴリズム（packages/media/sync）

1. 両方の音声を 8kHz モノラルに変換し、エンベロープ（振幅の包絡線）に高域強調をかける。話し声のアタック（子音や拍手）が鋭いピークになるようにする
2. FFT による相互相関で、全体のオフセットの候補を求める（探索範囲は既定で ±10 分）
3. **信頼度** = 1位のピークの高さ ÷ 2位のピーク（1位から 0.5 秒以上離れたもの）の高さ。この比と、正規化した相関の値の両方を見る
4. 1位のピークの周りで放物線補間をして、サンプル単位（1/8000秒）まで詰め、フレーム単位に丸める
5. **ドリフトの推定**（素材が 10 分以上のとき）: 素材を 60 秒の窓に区切り、窓ごとにオフセットを求めて、時刻に対して直線で当てはめる。傾きがドリフト（例: 1.00002 = 1時間で 72 ミリ秒）。外れた窓は除く（RANSAC）
6. ドリフトが 1 フレーム/時間を超えるときは、書き出し時に音声の時間を伸縮して補正する（映像はフレームの間引き・複製で合わせる）

### 補助手段

- **同期マーカー**: 収録開始時に、画面全体を白く光らせ、1kHz のビープ音を 100 ミリ秒鳴らす（オプション）。別撮りのカメラに画面が映っていれば映像のフラッシュでも、映っていなくても音で同期できる
- **拍手**: 手で拍手しても同じ効果がある。撮影画面のヘルプで案内する
- **タイムコード**: 素材に SMPTE タイムコードがあれば、初期値として使う（音声の相関で確認する）

### 信頼度が低いとき

| 状態 | 対応 |
|---|---|
| 比が 3 以上、相関が 0.5 以上 | 自動で確定 |
| 比が 1.5〜3 | 判定モデルに、両方の候補の前後のフレーム（口の動きと音声の波形の画像）を見せて、どちらが正しいかを選ばせる |
| 比が 1.5 未満、または音声がない | 人の確認待ち。アプリで2つの映像を並べ、フレーム送りで手動で合わせる |

## 撮影補助

- **カンペ**: `script.md` を、カメラの近くに置ける小さなウィンドウに流す。速さは喋る速さに合わせる（文字起こしの進み具合を見て自動でスクロールする。オプション）
- **カウントダウン**と**録画中の表示**（録画していることが一目で分かる赤い枠）
- **レベルメーター**と**ピークの警告**（音割れは編集で直せないので、撮影時に知らせる）
- **テイク**: 撮り直しは同じプロジェクトにテイクとして追加する。編集ではテイクをまたいで区間を選べる（言い直しのうち、良いほうを判定モデルが選ぶ）

## OSごとの注意点

| OS | 注意点 |
|---|---|
| macOS | 画面収録・カメラ・マイクの許可が必要（初回に案内）。PCの音声のループバックは macOS 13 以降。Info.plist に各権限の説明文を書く |
| Windows | PCの音声は WASAPI のループバック。カメラは他のアプリが使っていると開けないので、分かりやすいエラーを出す |
| Linux | Wayland では画面の選択に xdg-desktop-portal（PipeWire）を使う。X11 とは別に動作を確認する |

PCの音声のループバックは、Electron のバージョンと OS の組み合わせで挙動が変わるので、実装時に3つのOSで確認する（[08](./08_quality.md) のリスク表）。
