# 17. アーカイブ（過去の動画と timeline.json を参照する）

最終更新: 2026-10-11

## 目的

過去に作った動画と、その `timeline.json` を、**いつでも見られて、エージェントが参考にできる**ようにする。「前のあの回と同じテンポで」「あの回の解説シーンの使い方を真似して」と頼めば、エージェントが過去の設計図を読んで、同じ作りを再現する。

`timeline.json` には「何を・なぜ・誰が・どれくらいの確信で」が入っているので（[15](./15_timeline_schema.md)）、過去の動画は**完成品であると同時に、編集の手本**になる。

## 何を残すか

プロジェクトを書き出す・投稿するたびに、アーカイブに1件を登録する（`~/.solocut/archive/`）。

| 残すもの | 内容 |
|---|---|
| `timeline.json` | 書き出した時点のもの（版ごと。プロジェクトの Git の履歴とも対応させる） |
| 概要 | タイトル、種類（技術／語り）、テンプレートとその版、出力先、長さ、作成日、章の構成と要点、`meta.goal` と `meta.audience` |
| 統計 | カットの数と平均の長さ、切った割合、ジャンプカット・ズームの頻度、字幕の数と強調の割合、効果音の回数、BGM の音量差、使ったシーンの型とその回数、画角の切り替えの回数 |
| 完成した動画 | 書き出したファイルの場所（プロジェクトの中。アーカイブにはコピーしない）と、プレビュー用の低解像度版（任意） |
| サムネイル・投稿の内容 | サムネイル、タイトル、説明文、タグ、投稿先の URL、公開日 |
| 過程 | フィードバックの一覧と対応、要確認だった判断と人の決定、`learn` でテンプレートに取り込んだ直し |
| 使った素材 | 素材の id とライセンス（同じ素材を使い回すため） |

元の素材（収録したファイル）はプロジェクトに残す。アーカイブは**軽い索引と設計図**だけを持つので、何百本あっても重くならない。プロジェクトのフォルダを消した場合も、`timeline.json` と概要・統計・サムネイルは残る（動画は見られなくなるが、作りは参考にできる）。

索引は `~/.solocut/archive/index.sqlite`（全文検索つき）。各回の実体は `~/.solocut/archive/<id>/`（`timeline.json`、`summary.json`、`stats.json`、`thumbnail.jpg`、`feedback/`）。

## エディタの画面

「過去の動画」の画面:

- サムネイルの一覧（新しい順、テンプレート・種類・出力先・タグで絞り込み、全文検索）
- 1本を開くと、プレビュー、章の構成、統計、タイムラインの全体図（区間・字幕・シーン・効果音の配置が一目で分かる）、投稿の URL を表示する
- 「この回を参考にする」で、今のプロジェクトの参考に登録する（下記）
- 2本を選んで「比べる」で、統計とタイムラインの全体図を並べる

## エージェントからの参照

| コマンド | 内容 |
|---|---|
| `solocut past list [--kind tech] [--template talk-youtube]` | 過去の動画の一覧 |
| `solocut past search "Claude Code 設定"` | タイトル・要点・字幕・説明文を全文検索 |
| `solocut past show <id>` | 概要と統計（まず読むもの。コンテキストを節約） |
| `solocut past timeline <id> [--range 00:01:00-00:02:00] [--only scenes]` | 過去の `timeline.json` の一部を読む（[15](./15_timeline_schema.md) の `tl` コマンドと同じ読み方） |
| `solocut past compare <id> [--to current]` | 過去の回と今のプロジェクトの統計・作りの違い |
| `solocut past reuse <id> --what scenes,sfx-rules,caption-style` | 過去の回の作りの一部を、今のプロジェクトに当てはめる差分を作る |

`solocut mcp` でも同じ機能を出す（[12](./12_competitors.md)）。

## 今のプロジェクトに「参考」を登録する

`timeline.json` の `meta` に参考にする過去の回を記録する。

```jsonc
"meta": {
  …,
  "references": [
    { "archive": "arc_2026-09-28_claude-code-tips", "use": ["pacing", "scenes", "sfx"], "note": "テンポと解説シーンの使い方を合わせる" },
    { "archive": "arc_2026-08-14_cursor-vs-claude", "use": ["thumbnail-style"] }
  ]
}
```

- `solocut next` は、参考が登録されているとき、各手順で「参考の回ではこうしていた」という要約をエージェントに渡す（例: rough-cut の手順では、参考の回の切った割合・平均のカットの長さ・残した区間の役割の分布）
- 判定モデルのチェックに「参考の回との違い」を加えられる（例: 「参考の回よりテンポが大きく遅い」を警告）
- 用意済みのプロンプトに追加する（[13](./13_prompts_and_autopilot.md)）:

| ID | ボタン | 内容 |
|---|---|---|
| `like-past` | 過去の動画を参考に作って | 選んだ過去の回を参考に登録し、その作り（テンポ、シーン、字幕、効果音、サムネイル）に合わせて編集する |
| `same-as-last` | 前回と同じ作りにして | 直前の回を参考にする（`like-past` の簡単版） |
| `compare-past` | 過去の回と比べて | 今の動画と過去の回を比べ、違いと改善点を報告する |

## 投稿後の数字（任意）

YouTube に投稿した回は、YouTube Analytics API（`yt-analytics.readonly`）で再生数・平均視聴時間・視聴維持率・クリック率を取り込める（任意。利用者が許可した場合だけ）。アーカイブの統計と並べると、「どんな作りの回が伸びたか」をエージェントが参考にできる（例: 「視聴維持率の高い上位5本のテンポに寄せて」）。

## 設定

```jsonc
// settings.json
"archive": {
  "autoRegister": ["export", "publish"],   // 登録するタイミング
  "keepPreview": true,                     // 低解像度のプレビューを残すか
  "analytics": { "youtube": false }        // 投稿後の数字を取り込むか
}
```
