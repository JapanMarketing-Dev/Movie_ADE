# 09. ベンチマーク（参考動画からパターンを抽出する）

最終更新: 2026-10-11

## 目的

伸びている技術動画・語り動画には、字幕の出し方、効果音の入れ方、カットの間、BGMの音量などに**パターン**がある。参考にしたい動画の URL を渡すだけで、そのパターンを数値として取り出し、自分のテンプレートに取り込めるようにする。

```
URL を貼る（YouTube / TikTok）
  → アプリ内のブラウザで動画が開く（普通に再生するだけ）
  → 再生している間に、画面と音を解析する（映像・音声そのものは保存しない）
  → スタイルプロファイル（数値と特徴）＋代表的な場面の説明
  → 「テンプレートに取り込む」でテンプレートの差分を作る → エージェントが適用する
```

## お手本の動画を測る（2026-10-11 実装: `solocut bench analyze`）

お手本は**手元の動画ファイル**で渡す。利用者が選んだファイルか、アプリ内のブラウザで再生したお手本をアプリが録画したファイル（下の「取り込み方」。YouTube / TikTok からはダウンロードしない、yt-dlp も使わない）。

```sh
solocut bench analyze <動画ファイル> [--from 秒] [--to 秒] [--url <元の URL>] [--apply [--global]]
solocut bench apply <profile.json> [--template tech] [--global]   # 測った結果をあとからテンプレートへ
solocut bench unapply [--template tech] [--global]                 # お手本を外す
```

- アプリの流れ: 利用者がファイルを選ぶか、アプリ内のブラウザでお手本を再生して録画する → `bench analyze <ファイル> [--from --to --url] --json` → 結果の要約を見て、利用者が「この動画」（プロジェクトの中で `bench apply`）か「すべての動画」（`--global`）を選ぶ
- **アプリが録画したお手本は、他から見えない一時フォルダに書き、解析が終わったら（成功しても失敗しても）すぐ消す。アプリの終了時にも残っていれば消す**。yt-dlp は使わず、YouTube / TikTok から動画ファイルをダウンロードもしない
- `--json` のとき、`bench analyze` は stderr に進み具合を 1 行ずつ出す: `{"progress":{"task":"bench","fraction":0.35,"label":"音量を測っています","stage":"loudness"}}`（stage は cuts → loudness → sfx → captions → done）。最後に stdout に結果の JSON（`path`、`profile`、`patch`、`applied`、`warnings`）
- `bench apply` は何を入れたかを `<templates>/<id>/.benchmark.json` に残す。もう一度 apply すると前のお手本を外してから入れる（重ならない）。`bench unapply` はその分だけを上書きから取り除く（人が手で足した設定は残す。何も残らなければ上書きのフォルダごと消す）。適用されていなければ `not-applied` で終了コード 1

- ffmpeg / ffprobe だけで、1 秒ごとの数値（core の BenchmarkSample）を作る（@solocut/media `analyzeReference`）
  - カット: `select='gt(scene,0.3)',showinfo` のシーンの切り替わり → 1 ショットの平均の長さ、ジャンプカットの頻度
  - 音量: `ebur128` の瞬時ラウドネス（1 秒ごとの中央値）
  - 効果音: 10 ms ごとのエネルギーが直前 150 ms の中央値より 15 dB 以上跳ねた所（ポン・クリック・ドンのような立ち上がりの速い音。話し声の音節はゆっくり立ち上がる）。推定であり分類はしない
  - 字幕: 1 秒に 1 枚、160×90 のグレースケールで、画面の下 45%（と上 20%）に「とても明るい画素ととても暗い画素が隣り合う行」（白文字に暗い縁）が続く帯を探す → 位置・高さ・行数。帯の中身が変わった時を字幕の切り替わりとする。OCR（tesseract）は使わないので 1 行の文字数は分からず、テンプレートの値を保つ
- 結果は `~/.solocut/benchmarks/bench_<日時>.json`（プロファイル）と `.samples.json`（1 秒ごとの数値）。映像・音声そのものは保存しない
- `--apply`（または `bench apply`）で、プロファイルをテンプレートの上書き（`extends` した template.yaml）として書く
  - 既定はプロジェクトの中なら**この動画だけ**（`<project>/templates/tech/`）。`--global` で**これからのすべての動画**（`~/.solocut/templates/tech/`）。プロジェクトの外では `--global` と同じ
  - CLI はテンプレートを読むたびに上書きを重ねるので、「動画を完成させて」（finish）の流れは何もしなくてもお手本に合わせた設定で進む（字幕のスタイル・位置・行数・強調、効果音の規則と 1 分あたりの上限、BGM の音量、ジャンプカットのズーム）
  - 字幕の見た目（文字の大きさ・色・縁）は `captionLook` に入り、`solocut captions build` が字幕のスタイルをそれに寄せる（文字の大きさは画面の高さの 4.5〜9% に収める）
  - 1 本の 16:9 の動画なので、字幕のスタイルは `tech-bold` か `youtube-clean` から選ぶ（縦型のスタイルにはしない）。効果音はお手本が多くても 1 分に 8 回まで

## 取り込み方（ダウンロードしない）

- **動画ファイルはダウンロードしない**（yt-dlp なども使わない）。YouTube と TikTok の利用規約は、許可されていない方法でのダウンロードを禁止しているため
- アプリ内のブラウザ（Electron の WebContentsView、通常の Chromium）で、公式のプレイヤーをそのまま開く。再生の操作は利用者が行う（下の「規約上の注意」）。ログインやプレミアム会員の状態は、利用者のものがそのまま使われる
- 解析には、そのタブの映像と音声を `getDisplayMedia`（タブを指定）で受け取り、**メモリ上で解析して数値だけを残す**。フレームは解析が終わったらすぐ捨てる
- プロファイルに含める画像は、場面を説明するための**低解像度のサムネイル（字幕の位置を示す枠などの注釈付き）**だけにし、保存するかどうかは設定で選べる（既定は保存しない）
- 再生速度は等速（規約と、音の解析の正確さのため）。長い動画は「冒頭の3分」「指定の区間」だけを解析できる

## 抽出するもの

| 分類 | 項目 | 方法 |
|---|---|---|
| **字幕** | 位置（画面の下から何%）、文字の大きさ（画面の高さに対する比）、1行の文字数、行数 | OCR（文字の範囲）を一定間隔で |
| | 色、縁取りの太さと色、影、背景の帯の有無 | 文字の範囲の色を集計 |
| | 出し方（一括／単語ごと／カラオケ風ハイライト）、表示時間、切り替えの間隔 | 文字の範囲の変化を時系列で |
| | 強調の仕方（色を変える語、大きくする語の割合） | 文字の色・大きさのばらつき |
| | フォントの系統（ゴシック太字、丸ゴシック、明朝など） | 判定モデルに `choice` で聞く（候補は手元のフォント一覧） |
| **カット** | 1カットの平均の長さ、分布、ジャンプカットの頻度 | シーンの切り替わりの検出（PySceneDetect と同じ方法） |
| | ズーム（パンチイン）の頻度と倍率 | 連続するフレームの顔の大きさの変化 |
| | 図解・画像・B-roll の挿入の頻度と長さ | 判定モデルに「話している人が映っているか」を聞く |
| **音** | 話し声のラウドネス、全体のラウドネス | `ebur128` 相当の計算 |
| | BGM の有無、話し声に対する BGM の音量差（dB）、話している間に下げているか（ダッキング） | 音源分離（話し声と伴奏）→ それぞれの音量 |
| | BGM の雰囲気（Lo-fi、アップテンポ、ピアノなど）とテンポ（BPM） | 判定モデル（音声を扱えるもの）または特徴量（テンポ推定） |
| **効果音** | 効果音の回数（1分あたり）、どこに入るか（カットの瞬間、字幕の出現、強調語、場面の切り替え） | 立ち上がりの検出（話し声・BGM と分けたあと） |
| | 種類（ポン、シュッ、ドン、ピコーン、キラーン、タイピング、クリックなど） | 短い音の特徴量を、Solocut の効果音ライブラリの各カテゴリと比べて近いものを選ぶ |
| **話し方** | 話す速さ（1分あたりの文字数）、間の長さ | 文字起こし（端末内の whisper） |
| **構成** | 冒頭のつかみの長さ、チャプターの数、終わり方（まとめ・告知） | 文字起こしの要約（エージェントに頼む） |

## スタイルプロファイル

`~/.solocut/benchmarks/<id>/profile.json`（URL、タイトル、解析した区間と、上の数値）と `report.md`（人が読む要約）を作る。

```jsonc
{
  "source": { "url": "https://www.youtube.com/watch?v=…", "platform": "youtube", "analyzed": "00:00-03:00" },
  "captions": {
    "anchorY": 0.78, "heightRatio": 0.055, "charsPerLine": { "p50": 14, "p90": 18 }, "lines": 1,
    "fill": "#FFFFFF", "stroke": { "color": "#000000", "widthRatio": 0.12 }, "box": false,
    "reveal": "word-highlight", "emphasis": { "rate": 0.18, "color": "#FFE14D", "scale": 1.15 },
    "fontFamilyGuess": "gothic-heavy"
  },
  "cuts": { "avgShotSec": 2.4, "jumpCutsPerMin": 14, "punchIn": { "perMin": 3.1, "scale": 1.12 } },
  "audio": { "speechLufs": -15.2, "bgm": { "present": true, "relDb": -21, "ducking": true, "mood": "lofi", "bpm": 88 } },
  "sfx": { "perMin": 9, "on": { "cut": 0.2, "captionIn": 0.1, "emphasis": 0.55, "section": 1.0 }, "kinds": { "pop": 0.5, "whoosh": 0.3, "ding": 0.2 } },
  "speech": { "charsPerMin": 380, "pauseMs": { "p50": 180 } }
}
```

## テンプレートへの取り込み

- 「テンプレートに取り込む」を押すと、プロファイルからテンプレートの差分（`captions` のスタイル、`cut` の詰め方、`sfx` のルール、`audio.bgm` の音量差）を作り、変更前後を並べて見せる
- 字幕のスタイルは ASS のスタイルとして作る（色、縁取り、位置、出し方）。フォントは手元にあるフォントから最も近いものを選ぶ
- 効果音は、**参考動画の音を使うのではなく**、Solocut の効果音ライブラリから同じカテゴリの音を割り当てる（[06](./06_libraries.md) の素材ライブラリ）
- 複数の動画を選んで「共通のパターン」を作れる。各数値の中央値と、ばらつきの大きい項目（＝動画によって違う）を示す
- 取り込みの作業そのものもエージェントに頼める（「この3本のテンポに寄せて `talk-tiktok` を調整して」）

## テンプレートに追加する効果音のルール

```yaml
sfx:
  library: solocut-default
  rules:
    - on: emphasis        # 強調字幕が出るとき
      kind: pop
      probability: 0.55
    - on: section         # 章の切り替え
      kind: whoosh
    - on: cut
      kind: none
  maxPerMin: 10
  gainDb: -8              # 話し声に対する音量
```

効果音を入れる位置の最終判断（入れすぎていないか、言葉と被っていないか）は判定モデルが行う。

## 規約上の注意（重要）

YouTube の利用規約は、許可のないアクセス・複製・ダウンロード、ロボットなどの自動化した手段によるアクセス、複製防止の迂回を禁止している。TikTok も、許可のないデータやコンテンツの抽出（scrape / export / extract）を禁止している。そのため、次の設計にする。

- **再生・シーク・停止は、利用者自身が手で行う**。アプリが自動で再生したり、ページを巡回したりしない
- フレームと音声はメモリ上で処理して、すぐに捨てる。ディスクには書かない
- 顔や名前などの個人を特定できる情報は、検出も保存もしない
- 複数の動画を自動で次々に解析する機能は作らない
- **解析の対象は、原則として自分の動画か、許可を得た動画**とし、画面にもそう明示する
- 日本の著作権法 30条の4（情報解析）が著作権の問題に効く可能性はあるが、利用規約は契約なので別の問題として残る。**公開の機能として出す前に法務の確認を行う**

## その他の注意

- 解析するのは動画の「作り方の特徴」で、映像・音声・字幕の文章は保存しない
- プロファイルを他人と共有する機能は作らない（URL とタイトルを含むため）
- 各プラットフォームの規約は変わりうるので、規約を確認したうえで機能を提供する（実装時に最新の規約を確認する）
