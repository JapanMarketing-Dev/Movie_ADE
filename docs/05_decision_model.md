# 05. 判定モデル（decision model）・チェック・モザイク

最終更新: 2026-10-11

## 判定モデルは任意（既定はオフ。2026-10-11）

**判定モデルがなくても全体が動く。** 設定 `decision.provider` の既定は `off` で、API キーも要らない。どの手順も判定モデルを前提にしない（`solocut next --autopilot` は判定モデルなしで最後まで進む。CLI のテスト `packages/cli/test/onevideo.test.ts`）。判定モデルを入れたときだけ、下の各場面で使う。

判定モデルがないときの動き:

| 場面 | 判定モデルなし |
|---|---|
| カットの採否（rough-cut） | 規則で切る（無音・言いよどみ・NG の目印）。言い直しは規則ではどちらのテイクが良いか分からないので、切った範囲に needsReview を付ける。エージェントが `prompts/rough-cut.md` に沿って読み直し、自分で直す。人を待たない |
| カメラの切り替え（multicam） | `solocut multicam material` の `person`（人物のカメラ）と `suggestions`（決定的な目安）を見て、エージェントが決める。迷う切り替えには needsReview |
| 人物を中央に | 顔の解析（MediaPipe）からの計算だけ（[04](./04_templates_and_agents.md)）。判定モデルは使わない |
| サムネイル | 候補のフレームは画像の鮮明さ・露出の数値で選ぶ。画像はエージェントが Codex / Gemini のサブスクリプションに頼んで作る |
| チェック | 機械的チェックだけ。判断がつかないものは needs-human として人に回す（自動操縦は止めない） |

## 判定モデルとは

文章や画像を生成させるのではなく、**決まった形の問いに、型付きの答えと確率を返させる**モデル。Solocut では「この区間は残すか」「このフレームに問題はあるか」「この2つの同期候補のどちらが正しいか」といった、編集の細かい判断を任せる。

答えは確率で返るので、プログラムで扱える。

- 確率が高い／低い → 自動で確定する
- 中間 → 人の確認へ回す（テンプレートでしきい値を決める）

エージェント（Claude Code など）に1つずつ判断させるより速くて安く、何度やっても結果がぶれにくい。

## インターフェース（packages/decide）

形式は TypeSafe の System One に合わせる（状態＋問い＋画像 → 型付きの答え）。

```ts
type Question =
  | { id: string; kind: 'yesno'; text: string }                       // → 確率 p
  | { id: string; kind: 'choice'; text: string; options: string[] }   // → 選択肢ごとの確率
  | { id: string; kind: 'score'; text: string; min: 0; max: 1 };      // → スコア

interface DecisionRequest {
  state: Record<string, unknown>;   // 文字起こし、テンプレートの方針、区間の情報など
  questions: Question[];
  images?: { id: string; path: string; note?: string }[];  // フレーム画像
}
```

### プロバイダ

| プロバイダ | 用途 | 費用 |
|---|---|---|
| **エージェントCLI（既定）** | 利用者の Claude Code / Codex / Gemini CLI を非対話モード（`claude -p` / `codex exec` / `gemini -p`）で呼び、型の決まった問いに JSON で答えさせる。複数の問いを1回にまとめて呼び出し回数を節約する | **利用者のサブスクの範囲内（追加費用なし）** |
| **Ollama（ローカル）** | 完全に端末内で動かしたい人向け。画像も扱えるモデルを使う | 無料（GPU／メモリが必要） |
| TypeSafe（Jev） | 型付きの判断に特化した API | 利用者の API キー |
| OpenAI / Anthropic / Gemini の API | 画像を含む判断を、高い精度で行いたい場合 | 利用者の API キー |
| Cloudflare Workers AI | 安く API で動かしたい場合 | 利用者のアカウント |
| カスタム | 互換 API を持つ任意のエンドポイント | — |

- 既定は **`auto`**: インストールされているエージェントCLI（Claude Code → Codex → Gemini CLI の順）を使う。**Solocut は API キーを一切必要としない**。どれも無ければオフ
- API キーのプロバイダを選んだ場合は、「送るのはフレーム画像と文字起こしだけ」と明示して同意を得る
- API キーは OS の安全な保管庫（Keychain / DPAPI / libsecret）に入れる。エージェントには渡さない。エージェントは `solocut decide` を経由して使い、キーは Solocut の側で付ける
- **費用の上限**: 1プロジェクトあたり・1日あたりの上限（回数・金額）を設定でき、送る前に予約して超えないようにする。すべての問い合わせを `.solocut/decisions.jsonl` に記録する（問い、答え、モデル、トークン数、費用の概算）
- 同じ問いと同じ画像には、キャッシュした答えを返す（入力のハッシュで判断する）

## 判定モデルを使う場面

### 1. カットの採否（rough-cut）

候補の作り方（機械的に作る。ここでは判定モデルを使わない）:

- 無音区間（ffmpeg の `silencedetect` と音声のエネルギー）
- 言いよどみ（文字起こしの中の、テンプレートの `fillers` に当たる語）
- 言い直し（近い時刻に、似た文が繰り返されている箇所。文字起こしの類似度で見つける）
- 撮影時の NG の目印
- 長い間（話していない、画面も動いていない）

候補ごとに判定モデルに聞く。

```yaml
state:
  template_rules: (rules.md の要約)
  before: "…この設定画面を開いて、"
  candidate: "えー、あの、ちょっと待ってください"
  after: "右上の歯車を押します"
  kind: filler+pause
questions:
  - { id: cut, kind: yesno, text: "この部分を切っても、話の流れは自然につながるか" }
  - { id: content, kind: yesno, text: "この部分に、視聴者にとって必要な情報が含まれているか" }
```

言い直しでは「どちらのテイクを残すか」を `choice` で聞く（言い間違い、噛み、声の張り、表情を、両方の代表フレームと文字起こしで比べる）。

> 注意: whisper は「えー」などの言いよどみを文字に起こさないことが多い。initial prompt に言いよどみを含めた例文を渡す、文字起こしの単語と単語の間の音声のエネルギーを見る、の2つで補う（[08](./08_quality.md) のリスク表）。

### 2. 字幕（captions）

- 改行の位置: BudouX で文節の切れ目の候補を出し、候補が複数あるときは判定モデルに選ばせる
- 強調語: 1行に1つまで、強調する語を `choice` で選ぶ
- 誤字の修正: 固有名詞・専門用語の誤変換の候補（テンプレートと `script.md` の用語集から）を出し、置き換えるかを `yesno` で聞く

### 3. フレーム単位の最終チェック（check）

チェックは**機械的チェック → 判定モデル**の順に行い、機械で分かるものに判定モデルを使わない。

| チェック | 機械的に見るもの | 判定モデルに聞くもの |
|---|---|---|
| `black-frames` / `freeze` | ffmpeg の `blackdetect` / `freezedetect` | 意図的な暗転か、事故か（前後のフレームと区間の理由を見せる） |
| `loudness` / `spec` | `ebur128`、ffprobe（解像度、fps、コーデック、長さ、ビットレート） | ― |
| `audio-clicks` | カットの境目での音声の不連続（サンプルの跳び） | ― |
| `cut-boundaries` | 各カットの**前後それぞれ2フレーム**を `solocut frame` で取り出す。1〜2フレームだけの切れ残りの区間を機械で検出する | 「目を閉じかけ／口が開いたまま／不自然な表情で切れていないか」「つながりで違和感のあるジャンプがないか」 |
| `caption-safe-area` | 字幕の描画範囲を計算し、出力先のセーフエリアと比べる（画像は使わない） | ― |
| `caption-face-overlap` | 顔の検出範囲と字幕の範囲の重なり | 重なっている場合、見づらいか（口元か額か、など） |
| `pii-on-screen` | OCR で、メールアドレス・電話番号・APIキーらしき文字列を正規表現で拾う。モザイクの範囲で覆われているかを計算する | OCR が拾えない映り込み（通知のポップアップ、ブラウザのタブ、個人の写真）の有無を `choice` で聞く |
| `camera-switch` | 同じカメラが続いた長さ、切り替えの位置が文の切れ目か（文字起こしの時刻） | 切り替えの前後のフレームで、不自然な切り替え（同じ画角どうし、目線が外れている、ピンぼけ）がないか |
| `mosaic-tracking` | モザイクの範囲が、追跡対象から外れていないか（追跡の信頼度） | モザイクから対象がはみ出して見えていないか |

**フレームの選び方**（全フレームは見ない。費用と時間のため）:

- カットの境目の前後（必ず）
- 字幕の出始めと切り替わり（必ず）
- モザイクの区間は、追跡の信頼度が低いフレームと、0.5秒ごと
- それ以外は、シーンの切り替わりと、2秒ごとのサンプル

結果は `checks/<run-id>/report.md` に、不合格の項目ごとにタイムコード・画像・理由・直し方の候補をまとめる。エージェントはこれを読んで直し、`solocut check --only failed` で再確認する。

### 4. その他

| 場面 | 問い |
|---|---|
| 同期（[03](./03_recording_and_sync.md)） | 2つのオフセット候補のどちらが、口の動きと音が合っているか |
| ショートの切り出し | この区間は、単体で見て面白い・分かるか（スコア） |

## 人の確認（要確認の一覧）

判定モデルの答えが中間だったもの、チェックで判断がつかなかったものは、アプリの「確認」画面にまとめて出す。

- 1件ごとに、フレーム画像・前後の再生・判定モデルの答えと確率を表示する
- キー操作で「採用／却下」を素早く決められる（`J` / `K`、矢印で次へ）
- 人の決定は `history.jsonl` に人の操作として記録し、エージェントの `solocut next` にも反映される
- 人の決定と判定モデルの答えの食い違いを記録する。テンプレートのしきい値を見直す材料にする

## モザイク

### 対象と検出

| 対象 | 検出方法 |
|---|---|
| 画面に映った文字の個人情報（メール、電話、APIキー、住所、カード番号など） | OCR（PaddleOCR / Tesseract）＋正規表現。判定モデルで「個人情報か」を確認する |
| 通知、ポップアップ、特定のアプリのウィンドウ | 画面収録時の操作ログ（どのウィンドウが前面か）と、判定モデルによる画像の判断 |
| 第三者の顔 | 顔検出（MediaPipe / YuNet）。本人の顔は、撮影時のカメラのトラックの顔と照合して除く |
| ナンバープレート、表札など | 判定モデルに範囲の候補を出させ、人が確認する |
| 手動 | 確認画面やフィードバックのペンで範囲を囲む →「モザイク」を選ぶ |

### 追跡

- 検出したフレームから前後へ追跡する（OpenCV のトラッカー、または一定間隔で検出をやり直して補間する）
- 画面収録の場合は、ウィンドウやスクロールの動きが大きいので、OCR を一定間隔でやり直し、同じ文字列の範囲を結んでいく
- 範囲は安全側に**少し大きく**取り、追跡の信頼度が下がったフレームでは範囲を広げる

### タイムラインでの表現

```jsonc
"masks": [
  {
    "id": "m1", "kind": "pixelate",          // pixelate（モザイク）| blur（ぼかし）| fill（塗りつぶし）
    "reason": "pii:email", "source": "t1.screen",
    "track": [ { "frame": 120, "box": [412, 88, 260, 28] }, { "frame": 180, "box": [412, 40, 260, 28] } ],
    "confidence": 0.93, "createdBy": "auto"
  }
]
```

- 範囲は**元素材の座標**で持つ。レイアウトを変えても（ワイプにしても縦に切り出しても）、モザイクは対象についていく
- 書き出しでは、ffmpeg の `crop` → `scale`（縮小・拡大）／`boxblur` → `overlay` を、範囲の補間に合わせてかける
- **モザイクは書き出しの最後ではなく、元素材に一番近い段階でかける**。拡大やリフレームによって、モザイクの外側の情報が見えてしまうのを防ぐ
- `pii-on-screen` と `mosaic-tracking` のチェックで、かけ忘れと追跡外れをフレーム単位で確認する
